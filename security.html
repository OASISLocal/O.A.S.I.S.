Home / Security

Control stays with you.

An assistant that can touch your PC must prove it behaves. OASIS runs every action through three gates: a risk level on each tool, your per-tool permission, and mandatory confirmation for anything destructive. Telemetry ships off. Security is a design goal, not a guarantee that every generated answer or action is correct.

Permissions

Allow, deny, or ask — per tool.

Each of the 80+ tools declares what it can touch. You set each one to allow, deny, or ask every time, in Settings → Permissions. Microphone, screen and files have their own master switches on top.

LevelExample toolsBehavior
Lowsystem_info, file_search, wifi_infoRuns automatically
Mediumwrite_file, clipboard_control, open_urlFollows your per-tool setting
Highcode_agent, python_sandbox, run_workflowConfirmation required
Criticalsystem_control, kill_process, system_cleanupExplicit confirmation, every time

Nine high-impact tools (custom_command, system_control, kill_process, system_cleanup, clipboard_control, code_agent, python_sandbox, file_manager, run_workflow) can never run silently — even if a permission says otherwise.

Sandbox

Code runs in a cage first.

Generated code executes inside an isolated Docker sandbox with memory and CPU limits — never directly on your system. You review the diff before anything it produces touches your files. Skip Docker and code execution simply stays off; everything else keeps working.

Storage

Encrypted vault, local folder.

Secrets live in an encrypted local vault, not in config files. Models, memory and settings live in %LOCALAPPDATA%\O.A.S.I.S.\ — a folder you can open, back up, or delete. A PIN lock protects shared machines, and an action log records what the assistant did.

Telemetry

Off unless you say otherwise.

There is no usage tracking, no crash reporting, no account system. The only outbound channel that exists is an optional diagnostics webhook you configure yourself. Maximum-privacy mode is the default, not a toggle you have to find.

Known limitations

What this is not.

  • Risk levels classify tools, not model output. The model can still be wrong; confirmations protect actions, not answers.
  • The sandbox needs Docker. Without Docker, code execution is simply unavailable — nothing else changes.
  • Permissions are local. Anyone with access to your Windows account and the app data folder can change them.
  • Network tools are only as trustworthy as their provider — that is why they are opt-in and never silent.
  • Beta software. Report anything unexpected rather than assuming it is intended.

Disclosure

Found a hole? Tell us.

Report security issues on GitHub Issues — include your Windows version, app version and steps to reproduce. Please don't probe other people's machines with it.
