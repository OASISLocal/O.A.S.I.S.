Home / How it works

Everything happens inside this box.

A local AI assistant is a program that runs its AI model on your own hardware instead of calling a server. With OASIS, your words are transcribed on your PC, understood by a model stored on your disk, and answered with tools that live on your machine. The internet is only needed to download the app and a model — afterwards, it's optional.

local workflow · 0 external callsnetwork: unused

Simplified, but honest: there is no hidden sync step. The server component listens on localhost only.

Step by step

What happens when you speak.

1. Your PC listens locally.

Press to talk, or say the wake word. The microphone stream goes to an on-device recognizer, never to a transcription API. Background noise gets filtered; you can interrupt the reply mid-sentence and it stops, like a person would.

2. A model on your disk thinks.

The text reaches an open AI model (Llama, Gemma, Qwen and friends) running locally. It reads the conversation, checks its memory of you, and decides: answer directly, or use a tool. Small models answer fast on CPU; bigger ones run better with a GPU.

3. Hands, not just words.

When action is needed, the model calls one of 100+ declared tools — set a timer, lower the volume, read a PDF, run code in an isolated sandbox. Risky tools (deleting, shutting down, executing) pause for your explicit approval first.

4. It remembers — on your disk.

Exchanges, notes and documents land in a local database with semantic search, so "that electricity total from last spring" is retrievable months later. Delete by item, by type, or by file whenever you like.

Trust, technically

How you can verify all this.

  • Pull the plug to prove it. With a model downloaded, everything above keeps working offline. That's the whole test.
  • Watch the network. The app's server binds to localhost; there is no account system to phone home to.
  • Open the folder. Models, memory and settings live in %LOCALAPPDATA%\O.A.S.I.S.\ — plain files you can inspect.
  • Read the code paths. Per-tool permissions, an action log and an encrypted local vault are in the app today, not on a roadmap slide.
